Add sign-in to an app with Clerk, without writing any code yourself

In 40 minutes you'll fork a small web app called Vibe Board, connect it to Devin, and prompt Devin to plan and build authentication with Clerk: sign-up, sign-in, a private dashboard, and a user menu. Then you'll make it your own.

Enter your GitHub username at the top. Every link and prompt on this page fills in with it, and your progress is saved in this browser.

Before you start

do this before the event

You'll need three things ready. Setting them up takes about 10 minutes.

  1. A GitHub account. Any personal account works (sign up).
  2. Devin Pro, activated with your event coupon. Sign up at app.devin.ai, open Settings → Plans, pick Pro, and enter the coupon code you received from the organizer at checkout.
  3. GitHub connected to Devin. Go to Settings → Connections and connect GitHub. If GitHub asks which repositories Devin can access, choosing All repositories saves a step later.
Checkpoint: your Devin plan page shows Pro, and GitHub shows as connected under Connections.

You don't need a Clerk account. Devin will create a temporary development app that you can claim at the end.

1

Fork the template repo

4 min

The template is a small Next.js app. The landing page is public, and there's a /dashboard that's meant to be private but isn't protected yet. You'll fork it so Devin can work on your own copy.

Fork on GitHub ↗ View the template
  1. Choose your personal account as the Owner and keep the name devin-clerk.
  2. Untick "Copy the main branch only". That brings the solution branch along, which is handy if you fall behind.
  3. Click Create fork.
Checkpoint: <you>/devin-clerk opens and shows the Vibe Board README.
2

Connect your fork to Devin

5 min
  1. Open Devin → Settings → Connections and click your GitHub connection. Check that <you>/devin-clerk is in the list of available repositories.
    My fork isn't listed

    When you connected GitHub, you probably chose "Only select repositories". On GitHub, go to Settings → Applications → Installed GitHub Apps, click Configure next to Devin, add devin-clerk, and save. Then reload Devin.

  2. Go to the Devin home page and start a new Agent session. If there's a repository picker, choose <you>/devin-clerk.
  3. Keep the tab open. You'll paste the first prompt in the next step.
Devin reads AGENTS.md in your repo before it starts. It covers the project's commands and the Clerk rules, e.g. "use the Clerk CLI in accountless mode" and "never commit keys". That's why your prompts can stay short.
3

Ask Devin for a plan

7 min

Start by asking for a plan, not code. You'll review it and steer it before anything gets built.

Prompt 1: Plan (don't code yet)
Repository: {{repo}}

I want to add authentication to this app with Clerk. Only write a plan for now: don't change any code until I approve it.

Requirements:
- Set up Clerk with the Clerk CLI in accountless mode, following the rules in AGENTS.md. I don't have Clerk keys.
- Signed-out visitors see "Sign in" and "Sign up" buttons in the header. Signed-in users see their avatar menu instead.
- /dashboard requires sign-in and greets the user by first name.
- /api/notes returns a 401 JSON error when signed out.
- The landing page (/) stays public.

In the plan, list the files you'll create or change, how you'll protect routes, and how you'll check that it works. Keep it short.

Review the plan

When Devin replies, check that the plan:

  • runs npx -y clerk@latest init instead of asking you for keys,
  • protects /dashboard (in proxy.ts or on the page) and /api/notes, and leaves / public,
  • says how it will verify the result (lint, build, trying it in a browser).

Then reply with one change of your own. For example:

Example follow-up
Looks good. One change: style the Clerk components with the accent color from app.config.ts.
Checkpoint: Devin shows an updated plan that includes your change and is waiting for your go-ahead.
4

Build it and try it out

11 min
Prompt 2: Implement and verify
The plan is approved, go ahead and implement it. When you're done:
1. Run lint, typecheck and build, and fix any errors.
2. Start the dev server and share a live preview with me.
3. Open a pull request with a short description.
Don't commit .env.local or the .clerk folder.

This usually takes 5–10 minutes. While you wait, follow along in the session timeline and watch Devin run the Clerk CLI, edit files and run checks.

Try it in the preview

  1. Open the preview link Devin shares. You should see Sign in and Sign up in the header.
  2. Click Sign up and use a test email with +clerk_test in it, like yourname+clerk_test@example.com. When Clerk asks for a verification code, enter 424242. No real email gets sent.
  3. You should land on /dashboard, greeted by name, with your avatar in the header.
  4. Sign out from the avatar menu and open /dashboard again. You should be sent to the sign-in page.
  5. Open the pull request Devin created on your fork and skim the diff. Look for proxy.ts, the ClerkProvider in app/layout.tsx, and the new sign-in and sign-up pages.
Checkpoint: you signed up as your first user, the dashboard is only visible when you're signed in, and there's an open PR.
Something looks wrong in the preview

Tell Devin exactly what you saw, the way you would with a teammate. For example: "After signing up I land on / instead of /dashboard. Fix it and update the preview."

5

Make it yours

7 min

Pick one option and send it in the same session. If you're unsure about the approach, start with "Plan this first:" as in step 3.

A · Rebrand the app 
Rebrand the app as "<your idea>": update the name, tagline, emoji and accent color in app.config.ts, change the sample notes in data/notes.json to fit the new theme, and make the Clerk sign-in and sign-up screens match. Update the preview and push to the same PR.
B · Private notes per user 
Let signed-in users add their own notes from the dashboard. Save each note with the user's Clerk user ID (in memory or a JSON file is fine) and only show users their own notes, plus the sample ones. /api/notes should return only the signed-in user's notes. Update the preview and push to the same PR.
C · Branded sign-in pages 
Redesign the /sign-in and /sign-up pages with a two-column layout: our branding and tagline from app.config.ts on the left, the Clerk component on the right. Stack them on mobile. Update the preview and push to the same PR.
D · Profile page 
Add a /profile page that only signed-in users can open, using Clerk's UserProfile component, and link to it from the header. Update the preview and push to the same PR.
E · Teams (advanced) 
Enable Clerk Organizations with the Clerk CLI and add an OrganizationSwitcher to the header. Scope dashboard notes to the active organization, with a personal board when no organization is selected. Update the preview and push to the same PR.
Checkpoint: the preview shows your change and the PR has a new commit.
6

Next steps

2 min
  • Keep your Clerk app. The keys Devin used belong to a temporary, unclaimed Clerk app. To keep it, click the Clerk banner in your preview and claim it into a free Clerk account. From the Clerk dashboard you can then turn on Google or GitHub sign-in.
  • Merge your PR on your fork once you're happy with it.
  • Deploy it. Ask Devin: "Walk me through deploying this app to Vercel with my Clerk keys set as environment variables."
  • Speed up future sessions. Ask Devin: "Set up your environment for this repository." and approve the suggestion. New sessions then start with dependencies already installed.
  • Learn more: Clerk docs · Devin docs.

Troubleshooting

Devin asks me for Clerk API keys

Reply: "I don't have keys. Use accountless mode as described in AGENTS.md: run npx -y clerk@latest init."

I don't see a preview link

Ask: "Share a browser preview of the dev server on port 3000." You can also open the session's Desktop tab to watch Devin's browser.

The verification email never arrives

Sign up with an email that contains +clerk_test (e.g. yourname+clerk_test@example.com) and use code 424242. Clerk development apps accept these without sending mail.

I'm running behind 
Compare my branch with the `solution` branch of this repository and finish whatever is still missing from Prompt 2. Then share a live preview.

If you ticked "Copy the main branch only" when forking, you can browse the solution on the template repo instead.

Devin changed something I didn't ask for

Say so directly: "Please revert the change to X. Keep the diff limited to the auth work." Short, specific feedback works best.
